# Routing Engineering

Design loop-free, verifiable IPv4 routing across Packet Tracer routers and Layer 3 switches.

## 1. Static & Default Routing

- Prefer **next-hop IP** (`ip route <net> <mask> <next_hop>`) on multi-access Ethernet segments; on point-to-point serial links you may use next-hop IP or exit interface.
- Default route (`ip route 0.0.0.0 0.0.0.0 <next_hop>`) belongs on stub/branch edges pointing upstream.
- **Floating static backup:** append an administrative distance higher than the primary dynamic protocol (e.g., `115` > OSPF `110`, or `95` > EIGRP `90`).
- Always verify **bidirectional routing** (both forward and return paths exist on every hop).

## 2. OSPFv2 Best Practices

- Enable `ip routing` first on L3 switches (`3560-24PS`, `3650-24PS`).
- Set deterministic `router-id` (e.g., `1.1.1.1`) under `router ospf <pid>`.
- Use exact inverse subnet wildcard masks in `network <net_ip> <wildcard> area <area>` (compute via `subnet_calculate` when unsure—never guess).
- Mark LAN/SVI user-facing interfaces as `passive-interface <iface>` (or `passive-interface default` + `no passive-interface <transit_if>`) so hello packets are not leaked toward end hosts.
- Advertise upstream default routes into OSPF with `default-information originate` (on the ASBR/edge router holding a default route).
- Confirm neighbor states reach `FULL` (or `2WAY` between DROthers) via `show ip ospf neighbor` before testing end-to-end reachability. Common adjacency blockers: mismatched subnet/mask, area ID mismatch, hello/dead timers, passive-interface on a transit link, or duplicate router ID.

## 3. EIGRP & RIPv2

- **EIGRP:** Always include `no auto-summary` (`router eigrp <asn>`) and exact wildcard masks for VLSM networks (`network <net> <wildcard>`). Verify AS number match and `show ip eigrp neighbors`.
- **RIPv2:** Use `version 2` and `no auto-summary` to avoid classful summarization bugs across discontiguous subnets.

## 4. AgenticNet & Packet Tracer Routing Boundaries

- **Supported in AgenticNet `IOSGenerator` (`advanced` `configure_routing`, `configure_ospf`, `configure_eigrp`):** Static routes, RIPv2, OSPFv2, and EIGRP.
- **Not generated by `IOSGenerator`:** BGP, FHRP (HSRP/VRRP/GLBP), OSPF authentication templates, and IPv6 routing (OSPFv3/static IPv6). If a Packet Tracer `8.2.2` router model supports a feature natively in CLI (e.g., HSRP on `2911` or basic BGP where supported), configure it explicitly via `console_execute`, verify live output, and note any PT model limitations if the IOS parser rejects a command.
- `3560-24PS` / `3650-24PS` support static routing, RIP, OSPF, and EIGRP (with `ip routing`), but **do not support NAT/PAT** in Packet Tracer (`2911`/`1941`/`2811`/`4321` must handle NAT edge duties).

## 5. Verification Checklist

- `show ip route` (or `verify_lab` `route_exists` with `protocol_code`, `next_hop`, or `outgoing_interface`).
- `show ip ospf neighbor` / `show ip eigrp neighbors` / `show ip protocols`.
- Live `ping` (`connectivity_test` or `verify_lab` `reachable`) across every routed boundary.
